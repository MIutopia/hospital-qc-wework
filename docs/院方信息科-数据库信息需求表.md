### 1.2 已确认可用的表（[HIS数据库] 库）

质控系统将直接读取以下**反范式化宽表**（已含全部需要的字段）：

| 表/视图名 | 说明 | 关键字段 |
|-----------|------|---------|
| `hospitalisation_case_man` | 住院病案首页 | 住院号、姓名、性别、入院/出院时间、入院/出院科室、主任/主治/住院医师、中西医诊断、手术编码/名称、病历质量、质控日期 |
| `[HIS数据库]_hospitail_rceord` | 住院入院记录 | 患者姓名、入院时间、记录时间、**主诉**、**现病史**、既往史、体格检查、中西医初步诊断 |
| `住院病案首页表`（视图） | 当日病案首页（去重） | 同病案首页全部字段 |
| `住院入院记录表`（视图） | 当日入院记录 | 主诉、现病史等 |
| `住院出院记录表`（视图） | 当日出院记录 | 出院诊断、出院医嘱、治疗经过 |
| `住院病程记录表`（视图） | 近2日病程记录 | 病案名称、病案内容、记录医生、书写时间 |
| `住院短期医嘱表`（视图） | 当日短期医嘱 | 医嘱内容、医嘱时间、执行医生 |
| `住院长期医嘱表`（视图） | 当日长期医嘱 | 医嘱内容、停止时间、停止医生 |
| `record_of_discharge`（视图） | 出院记录 | 出院诊断、治疗经过 |

> **门诊数据（`records` 库）：** 如后续质控需要门诊病历（`out_medical_records`），再补充授权。

### 1.3 增量同步机制（已确认）

HIS 数据仓库已有完善的增量同步机制，质控系统直接复用：

| 机制 | 说明 |
|------|------|
| `SyncControl` 表 | 记录各表同步进度 |
| 增量同步 SP | 每 5 分钟运行（`usp_SyncXXX_Incremental`） |
| 夜间追赶 | 每晚 02:00 自动补齐历史（90天/批） |
| **增量识别字段** | 各表均有 `录入时间`（`d_time_input`）时间戳字段 |

## 五、数据用途与安全说明

| 数据类型 | 使用方式 | 安全措施 |
|---------|---------|---------|
| 病例数据 | 仅存院内业务数据库（HospitalQC），不传出医院内网 | 与 HIS 同服务器部署 |
